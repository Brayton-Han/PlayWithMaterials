## 详细说明

### OQ-01 预计投入时长未给出数值
- **出处**：PRD 项目目标 3"预计投入包含开发、验证和交付整理；请在 README 记录实际投入与取舍"。
- **问题**：只说"预计投入"，没有给出具体时长（如 X 天 / Y 小时），无法据此裁剪 P1 范围。
- **影响**：决定 P1（视觉打磨、Compose、批量查询等）纳入多少。
- **临时默认**：先完成 P0 + F-17（Compose），P1 其余项按剩余时间取舍并在 README 说明。

### OQ-02 用户身份方案与鉴权强度 — 已确认
- **结论（2026-11-04）**：需要密码；需要账户设置页，只保留密码修改（Reset）和 Delete Account 两个操作。截图中的 Manage Billing、Terms of Service、Privacy Policy、Subscription Policy 不实现。
- **由此带出的新问题**：OQ-23（登录标识、注册、未登录浏览）、OQ-24（密码规则）、OQ-25（Reset 的含义）、OQ-26（删除账户）、OQ-27（账户信息展示）、OQ-28（会话有效期）。原问题第 5 点（文件 URL 是否鉴权）并入 OQ-23。
- **原问题记录**：
- **出处**：R-10"请自行设计用户身份与个人任务记录的管理方式"；R-08.2"切换用户时妥善清理"；截图 image/4.png 账户设置（邮箱、密码、Reset）。
- **问题**：
  1. 是否需要密码？还是用户名即身份（无鉴权）、或匿名设备身份即可？
  2. 截图 4 中的邮箱/密码展示是否属于要求范围（R-11.3 说题外功能不扩展，但截图又挂在 R-10 下）？
  3. 未确立身份时，能否浏览模板列表 / 详情？
  4. 需要演示"切换用户"，期望的演示方式是什么（退出后换名登录 / 下拉切换预置用户 / 两个浏览器）？
  5. 素材与结果文件 URL 是否也需要鉴权，还是不可猜测的随机 URL 即可？
- **选项**：A 用户名登录（无密码）；B 匿名设备 ID；C 用户名 + 密码；D 预置演示用户下拉切换。详见 requirements F-12。
- **临时默认**：A；模板浏览无需身份，素材/任务/历史需身份；文件使用随机 URL。

### OQ-03 分类层级与"全部" — 已确认
- **结论（2026-11-04）**：一级分类。由此一个模板只属于一个分类。
- **余项**：分类栏是否提供"全部"、分类排序规则仍按临时默认（提供"全部"并默认选中；按种子顺序排序），如有不同请告知。
- **原问题记录**：
- **出处**：R-02 示例只有一个 `category` 字段；UI-01 截图有两级（顶部 Video / workflow / Test Channel Classification，下面 All / Trending / video / Pets / Proposal & Wedding）。
- **问题**：需要一级分类还是两级？是否需要"全部"选项？一个模板能否属于多个分类（截图中 "video" 同时出现在一级与二级）？分类排序规则？
- **临时默认**：一级分类 + "全部"；一个模板仅属于一个分类；按种子顺序排序。

### OQ-05 上传时机 — 已确认
- **结论（2026-11-04）**：点击提交时，图片和制作参数在同一个请求中一起上传。
- **对设计的影响**（已写入 requirements F-03 ~ F-05、backlog T-030 ~ T-032、T-041）：
  - 不设单独的素材上传接口；选图后只在本地预览。
  - R-03.1 的"上传中和上传失败反馈"、R-07.1 的"素材上传中"对应提交请求发送文件的阶段（显示上传进度）；文件发完、等待服务端受理时为"提交中"。
  - 上传失败时整次提交失败，已选文件保留，可直接重新提交。
  - 服务端需要保证文件和数据库一致：校验或入库失败时不留下文件。
  - OQ-06、OQ-15 因此不再适用。
- **原问题记录**：
- **出处**：R-03.1"上传中和上传失败反馈"；R-03.3"不能只使用浏览器临时地址代替服务端可用的素材"。
- **问题**：是选图后立即上传到服务端（每张独立显示上传中/失败），还是点击提交时将图片与任务一起上传？
- **影响**：接口形态（独立素材接口 vs 单个 multipart 提交接口）、"上传中"与"提交中"两个状态是否同时存在、上传时是否需要知道 templateId。
- **临时默认**：选图即上传，提交接口只传 assetId 列表（R-07.1 将"素材上传中"和"提交请求中"列为不同状态，支持这一理解）。

### OQ-06 素材复用 — 已关闭
- **关闭原因**：OQ-05 确认提交时一起上传，每次提交都上传新文件，不存在复用已上传素材的情况。

- **临时默认**：同一任务内不可重复；跨任务允许复用同一 asset。

### OQ-13 服务重启后未完成任务的处理

- **临时默认**：倾向 B（保证前端最终停止轮询），但因涉及业务规则，待确认前仅在 README 说明现状。

### OQ-26 删除账户 — 主体已确认
- **结论（2026-11-04）**：
  1. 二次确认方式：在输入框中输入 `DELETE`；
  2. 数据保留（软删除，任务记录和文件都留在库中，但无人能访问）；
  3. 正在跑的任务废弃；
  4. ~~不能重复注册~~ → **补充确认（2026-11-04）**：注册时需要邮箱，注册后不能修改；登录用用户名 + 密码；账户删除后，相同邮箱可以再注册。已删除账户的用户名能否再用，拆到 OQ-31。
- **余项（非阻塞，按临时默认推进）**：
  1. ~~"同一邮箱"还是"同一用户名"~~：已由上面的补充确认解决。
  2. **"废弃"的任务记成什么状态**：临时默认为 `FAILED`，`failedStage` 是废弃时所处的阶段，`failureReason` = "账户已删除，任务已废弃"，不新增状态。备选是新增一个 `CANCELLED`（已废弃）状态，与"执行失败"区分开，但这会扩展 PRD 要求的状态集合。由于账户删除后没人能看到这些任务，这只影响数据库记录和 README 的说明。
  3. **`DELETE` 是否区分大小写**：临时默认为必须完全一致（区分大小写，不去除首尾空格）。
- **实现说明**（已写入 requirements F-28、backlog T-012 / T-042）：删除账户的事务中用条件更新把进行中的任务改为终态，执行器在下一次状态写入时发现影响行数为 0 就停止。正在执行的那一步会执行完，但不会进入下一步，也不会写入结果。
- **原问题记录**：
- **背景**：OQ-02 确认保留 Delete Account。这是不可逆操作，PRD 没有定义任何规则。
- **问题**：
  1. 二次确认方式：确认对话框即可，还是还要输入密码 / 输入特定文字？
  2. 数据处理：用户的任务记录、上传素材、结果文件是**物理删除**还是**软删除**（保留但不可访问）？
  3. 删除时仍在执行（PENDING / PROCESSING）的任务怎么处理：继续执行、立即标记失败、还是一起删除？
  4. 同一邮箱删除后能否重新注册？如果能，是否能看到以前的记录（不应该）？
- **临时默认**：确认对话框 + 输入当前密码；软删除用户并作废全部会话，任务和文件保留在库中但无人可访问；进行中的任务继续跑完；同一邮箱不可重新注册。
- **备注**：如果希望"重新注册同一邮箱"，软删除方案需要改为释放邮箱（如改写 login_id），或改为物理删除。

### OQ-31 已删除账户的用户名能否再被注册

- **临时默认**：永久占用，不能再用。

### DQ-01 ~ DQ-04 架构设计阶段新增问题 — 已确认
> 来源：[architecture.md §11](./architecture.md#11-本文涉及的未确定问题)。2026-11-04 全部确认。

- **DQ-01 模拟开发接口是否需要保护**：`/api/dev/simulation` 在 Compose 的 demo profile 下开放。**结论**：不需要登录，只用于本地演示；prod profile 下该接口不存在（返回 404），README 写明。
- **DQ-02 删除账户后文件链接是否失效**：OQ-26 要求删除后"任何人都不能通过界面或接口访问这些数据"，而 OQ-23 余项 2 的临时默认（文件 URL 不鉴权）会让已知链接在删除后仍能打开。**结论**：失效。`/files/uploads/**`、`/files/results/**` 需要登录，后端查库确认文件属于当前用户才返回，否则 404；已删除用户没有有效会话，其他人查不到归属。种子图 `/files/seed/**` 仍公开。新增任务 T-047。
- **DQ-03 是否返回 `failureCode`**：**结论**：返回。失败任务同时有机器可读的 `failureCode`（`SIMULATED_FAILURE` / `ASSET_MISSING` / `ASSET_INVALID` / `RESULT_WRITE_FAILED` / `ACCOUNT_DELETED` / `INTERNAL_ERROR`）和用户可读的 `failureReason`。OQ-11 的文案语言等其余部分仍待确认。
- **DQ-04 "确认密码"是否由服务端校验**：requirements v0.4 写有"两次密码不一致时服务端返回 400"，可理解为接口也要接收确认密码。**结论**：只在前端校验，接口不接收 `confirmPassword`；服务端仍校验密码规则。
